# Public API and richer exports

## Existing HTTP surface audit

Tomcat binds `127.0.0.1` and sends all prior routes to `DashboardServlet`. `/`, `/node`, `/analytics`, `/reports`, and `/reports/network` are UI routes. `/inspection/status`, `/inspection/history`, `/inspection/changes`, `/inspection/evidence`, `/analytics.json`, and `/analytics/snapshot.json` are internal browser endpoints and remain outside the stable contract. `/scanner/start`, `/scanner/stop`, and `/data/clear` are CSRF guarded mutations, never public API operations. `/export.csv` was an unbounded, network wide endpoint inventory with nested JSON and no spreadsheet formula protection. It now returns 410 with a migration pointer. Assets and JSP are UI internals.

The older UI history methods already use timestamp and occurrence ID cursors and limits of 100. UI listing loads and filters all projection rows in memory; this is not suitable as a public listing. `NetworkAnalytics` already uses read-only SQLite connections, a 31 day bounded window, and evidence row limits. `SqliteNodeStore` read methods provide domain occurrences, including deduplicated payloads attached to distinct inspection runs. Public API reads use a read-only store constructor that skips migration/initialization. Browser JSON uses Jackson but lacks a stable envelope and consistent error contract. Existing `sendError` pages are not public API errors. No authentication or CORS policy exists; the server listens on loopback.

## v1 contract

`/api/v1` is a separate read-only servlet. API v1 is a representation version, independent of SQLite schema v5. It returns small `apiVersion` envelopes, `data` for successful resources, `pagination` for collections, and `error.code` plus `error.message` for failures. JSON fields use camelCase, UTC ISO-8601 `Instant` strings, and JSON numbers for counts. The API root names resource families, limits, and `/api/v1/help`. Internal UI JSON is not part of v1. No OpenAPI artifact is added: a small hand-maintained contract and HTTP tests are simpler for v0.0.1.

Identity is the normalized 128 hex digit cryptographic public key. It is never an address. Listing is lexical by identity and yields only bounded public key IDs and detail links. Detail labels its selected row `latestProjection` and does not treat the row endpoint as canonical. Discovery receipts remain occurrences and carry source, provenance, time, and endpoint address, family, port, transport, and purpose. ENR evidence exposes outcome, structural and signature status, identity comparison, `usable()` trust, and record detail only on identity scoped pages. It does not expose raw RLP as a separate listing field. Enrichment remains address, dataset, and lookup time scoped. Inspection runs are separate occurrences with independent P2P, RPC, and Beacon evidence payloads; shared content hashes do not merge runs. Derived ChangeEvents carry derivation version, source IDs, and public source links where the kind is resolvable. A first observation remains a first observation, not a physical transition.

`NOT_TESTED`, `FAILED`, unavailable dataset, client conflict, unknown version, and null legacy timestamps retain their existing meanings. No synthetic online, hosting provider, node geography, canonical endpoint, observer ID, or disappearance state is introduced. Equal timestamps use occurrence IDs only as deterministic ties, not causal sequence. All analytics calls delegate to one `NetworkAnalytics.measure` call. Window semantics remain UTC `[start,end)` with maximum 31 days; `mode=all` uses existing evidence row safety limits and may reject large datasets.

## Pagination, errors, and limits

Collections default to 20 rows and allow at most 50; identity scoped CSV allows at most 99 rows. The 99 row bound permits a 100th occurrence to detect overflow through the existing read model's 100 row cap. A CSV request exceeding its requested limit fails with 413 rather than truncating. Cursors are URL safe base64 tokens and opaque to clients. Identity listing sorts cryptographic IDs lexically. Domain history uses existing descending timestamp plus occurrence ID ordering. Cursor identity/scope is checked; deleted or malformed cursors return 400. Client errors use 400, missing identity/occurrence 404, method rejection 405, safety limit 413. Unexpected errors use a generic 500 without SQL, paths, or traces. The API accepts GET and HEAD and rejects POST, PUT, and DELETE. It does not expose arbitrary sort columns, raw SQL, global fuzzy search, or unbounded filters. Unsupported query parameters are not part of the contract.

All v1 responses set `Cache-Control: no-store`. No CORS headers or rate limiter are added. Query bounds are not Internet facing rate limiting. Local/operator controlled exposure remains the security boundary; operational hardening is a later milestone. The API takes the scanner lifecycle monitor during requests to avoid Clear interleaving with response assembly. Separate reads are not a durable snapshot across independent scanner writes. After Clear, deleted identities are absent and old cursors become invalid when their source disappears. API state is fully recomputable and writes no durable truth.

## Exports and privacy

Network wide identity pages contain IDs only. There is no public global peer IP export. Address evidence is available for a specified cryptographic identity in bounded pages or CSV. Analytics CSV exposes aggregate metrics, units, denominators, unknown counts, overlap semantics, and scope, without peer addresses. CSV columns are fixed per export. Generic identity scoped evidence CSV carries typed JSON payload per occurrence so incompatible domains are not flattened into false columns. CSV text beginning `=`, `+`, `-`, or `@` gets a leading apostrophe before RFC style quoting; remote stored values are never changed. Download filenames are fixed server strings, with no request text reflected into headers. The response includes API version, generated time, and row unit headers. The identity and row type are present in rows. The request URL plus headers supplies export scope. There is no JSON download alias, ZIP, database dump, Parquet, or Arrow.

## Performance and security

The representative API uses prepared parameters for identity and cursor values; dynamic SQL table names come only from fixed internal switches. History queries use existing identity/time indexes. Identity listing merges indexed evidence IDs and projection IDs in SQLite; it is bounded in returned rows but its union scans source indexes, an accepted local performance cost at v0.0.1 scale. No index or migration was added. CSV and JSON pages buffer no more than 100 history occurrences. Large raw ENR fields are not duplicated as top level listing fields. Escaping is performed by Jackson for JSON and at the CSV boundary for spreadsheets. HTML help contains fixed text and no database values. Unknown paths and IDs yield safe errors. The server stays bound to loopback.

## Compatibility and freeze

Additive fields and future enum values may appear in v1; clients must ignore unknown fields and handle unknown enum values. Breaking representation or semantic changes require a future API version. Occurrence IDs are scoped source references and tie breakers, not chronology. This work introduces no schema v6, migration, collection, observer model, new probes, durable API cache, or new report measurement rule. Cryptographic identity, endpoint multiplicity, discovery receipts, historical observations, latest projection separation, independent protocol outcomes, `EnrEvidence.usable()`, derived ChangeEvents and rule versions, analytics semantics, and geography dataset scoping remain the frozen model. Hosting inference and missing-observation disappearance inference remain absent.
