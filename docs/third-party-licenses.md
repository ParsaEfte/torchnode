# Third-party licenses and source distribution

The MIT license covers TorchNode-owned source. It does not replace dependency licenses. [Notices](../THIRD_PARTY_NOTICES.md), [license evidence](release-validation.md), and the `third-party/` directory identify the candidate components and preserve upstream notices.

The Linux amd64, CGO-disabled helper inventory has 51 license entries. Two classifier unknowns were reviewed against actual upstream files: bloomfilter declares MIT in source headers, and NAT-PMP declares Apache-2.0 in its LICENSE and README. The bloomfilter module zip omits the repository-root MIT-LICENSE.txt. It has now been recovered from the exact tagged upstream archive after all Go files/go.mod matched the v2 subtree; the full original license and copyrights are preserved. Go assembly files are part of their respective upstream source packages; classifier warnings about assembly are not an independent license clearance.

The compiled geth dependency includes `trie/bintrie/bitarray.go`, which declares GPL-3.0-or-later, alongside LGPL-3.0-or-later library files. This is preserved in `third-party/go/github.com/ethereum/go-ethereum/GPL-source-declaration.txt`. It must not be relabeled entirely LGPL or MIT. The helper source remains available under its own MIT terms; the combined binary carries the applicable dependency obligations. Binary distribution/licensing disposition remains PENDING operator review, with corresponding-source materials prepared locally. No risk or obligation has been waived.

The Maven runtime inventory covers 46 components, including the native JFFI classifier. All published source JARs were obtained. Source JAR availability does not establish native-binary rebuild completeness. Lanterna declares LGPL, ECJ declares EPL-2.0, and JNR-POSIX lists multiple licensing options. The inventory preserves those declarations rather than inventing a single licensing choice. Standard license texts and dependency-specific copyright headers/notices are included. Unknown or contradictory future declarations must block distribution review.

## Reproduce the inventory

Use a disposable source checkout and the pinned release toolchains, not the production checkout build output:

```sh
mvn -B org.apache.maven.plugins:maven-dependency-plugin:3.7.0:list -DincludeScope=runtime -DoutputFile=target/runtime-dependencies.txt
mvn -B org.cyclonedx:cyclonedx-maven-plugin:2.9.1:makeAggregateBom -DincludeTestScope=false
mvn -B org.apache.maven.plugins:maven-dependency-plugin:3.7.0:sources -DincludeScope=runtime
```

Go license metadata was generated by go-licenses v2.0.0 with its tooling dependency x/tools upgraded to v0.52.0 for compatibility with Go 1.26. The exact tool module/sums and CSV are retained with the private build evidence. Run `go-licenses report ./...` with `GOOS=linux GOARCH=amd64 CGO_ENABLED=0`, and record `go list -deps -json ./...` under the same environment. Save them as `target/go-license-linux-amd64.csv` and `target/go-packages-linux-amd64.jsonstream`, then run `python3 tools/prepare-third-party-notices.py <isolated-root> --bloomfilter-source <tagged-bloomfilter-v2.0.3.tar.gz>`.

## Corresponding-source materials

The [private source-material bundle](release-validation.md) contains helper source plus a vendor tree, Maven runtime artifact/source JARs/POMs, application source/build instructions and checksums. Do not publish the binaries without the reviewed matching source/notice materials. Missing source or native rebuild coverage must remain an explicit distribution gate.

The helper source tree supports offline replacement and rebuilding with Go 1.26.11:

```sh
GOTOOLCHAIN=local GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -mod=vendor -buildvcs=false -trimpath -o out/torchnode-p2p-helper .
GOTOOLCHAIN=local GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -mod=vendor -buildvcs=false -trimpath -o out/torchnode-discovery-helper ./cmd/discovery
```

For the Java application, use Java 21 and Maven 3.9.16 with the supplied application source/POM. Dependency JARs and source JARs are supplied separately so a recipient can replace a library; the thin application JAR can also run with a replacement library first on the classpath. Maven build plugins may need ordinary repository access unless cached. These build instructions authorize no application startup, production data access or deployment.

The final image contains four Alpine package file sets and the pinned Temurin JRE. Image OS/JRE license and source-obligation review is a separate gate tied to the actual image SBOM, not covered solely by this application inventory.
